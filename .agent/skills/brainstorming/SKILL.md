# Brainstorming Ideas Into Designs

Use when the user wants to build something new — a feature, component, app, or system.

## Overview

Help turn ideas into fully formed designs through collaborative dialogue. Start by understanding the current project context, then ask questions one at a time to refine the idea. Present the design in small sections (200-300 words), checking after each section.

## Process

1. **Understand context**: Check project state (files, docs, recent commits)
2. **Refine idea**: One question per message, prefer multiple choice
3. **Explore approaches**: Propose 2-3 approaches with trade-offs, lead with recommendation
4. **Present design**: Break into 200-300 word sections, validate each
5. **Document**: Save to `docs/plans/YYYY-MM-DD-<topic>-design.md`, commit to git
6. **Next steps**: Offer to create implementation plan with `/write-plan`

## Key Principles

- One question at a time
- YAGNI ruthlessly
- Explore alternatives before settling
- Incremental validation
